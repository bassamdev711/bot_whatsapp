# وصلة — لوحة أحداث واتساب

**وصلة** تطبيق Next.js عربي يوفّر لوحة تحكم لربط حساب واتساب عبر **QR** أو **كود ربط الرقم**، ثم عرض أحداث الرسائل والحالات والوسائط داخل سجل تشغيل واضح.

> تبقى الواجهة وواجهات القواعد والمساعد على Vercel. أمّا اتصال WhatsApp Web الحي فيعمل داخل **عامل Node.js صغير مستقل**. لا يفتح المتصفح اتصال واتساب مباشرة، ولا يرى سر العامل أو بيانات جلسة Baileys.

## ما الذي بُني؟

| الجزء | الوظيفة |
|---|---|
| لوحة RTL عربية | حالة الاتصال، تدفق الأحداث، القواعد، ومؤشرات الجلسة. |
| ربط QR | إنشاء رمز فعلي من موصل واتساب عند الضغط على «إنشاء رمز حقيقي». |
| ربط برقم الهاتف | إنشاء كود ربط بعد إدخال الرقم بالصيغة الدولية. |
| سجل أحداث داخلي | يسجل بدء الجلسة، رمز QR، الاتصال، الرسائل الواردة، الحالات، الوسائط، وأخطاء القواعد. |
| قواعد رد قابلة للتحرير | أنشئ ردودًا من الواجهة، واختر العبارة المشغلة والنص والرقم المستهدف، ثم فعّلها صراحةً. |
| قوائم خدمات تفاعلية | أرسل قائمة خيارات رقمية ثم ردًا مخصصًا لكل خدمة يختارها المستخدم. |
| إدارة حالات قابلة للضبط | تأكيد مشاهدة حالة وتفاعل تلقائي اختياري، مع اختيار القلب أو رمز آخر واستثناءات وتخصيص لكل رقم. |
| سجل نشاط محفوظ | يعرض أحداث الجلسة والرسائل والقواعد ويحتفظ بها محليًا بعد تحديث الصفحة أو إعادة التشغيل. |
| إعدادات تشغيلية | تعرض حالة الجلسة والربط والخصوصية، وتتيح إعادة ضبط الجلسة صراحةً. |
| مساعد بسّام الشخصي | محادثة Gemini خادمية اختيارية مع تفعيل صريح، صرامة قابلة للضبط، وتعليمات خاصة محفوظة محليًا. |
| حماية الجلسة والإعدادات | تحفظ بيانات الاعتماد في Neon بعد تشفير AES-256-GCM؛ لا تُرفع إلى Git ولا تصل إلى المتصفح. |

## المتطلبات

يتطلب المشروع Node.js 22 أو أحدث وpnpm. الواجهة تصلح لـ Vercel، أمّا عامل واتساب فيحتاج عملية Node.js صغيرة تبقى متصلة لكي يستقبل الرسائل والحالات في وقتها.

```bash
pnpm install
pnpm exec next dev --port 3101
```

ثم افتح `http://localhost:3101` واختر **ربط حساب واتساب**. في التطبيق، افتح واتساب على هاتفك ثم اتجه إلى **الأجهزة المرتبطة** لمسح رمز QR أو إدخال كود الربط.

## بناء وتشغيل الإنتاج

استخدم قيمة صريحة لمتغير البيئة عند البناء:

```bash
NODE_ENV=production pnpm build
NODE_ENV=production pnpm start
```

في Vercel، تحفظ القواعد والتدفقات وإعدادات الحالات وإعدادات مساعد بسّام وسجل النشاط في Neon بدل الاعتماد على قرص محلي. يستخدم التطبيق `POSTGRES_PRISMA_URL` أولًا، ثم `DATABASE_URL_UNPOOLED`، ثم `DATABASE_URL` إذا كانت سلسلة PostgreSQL صالحة. ينشئ التطبيق جدول `wasla_documents` تلقائيًا عند أول طلب. لا تحتاج إلى إضافة متغير Neon آخر ما دامت المتغيرات التي أضفتها ظاهرة في بيئة Vercel.

أثناء التطوير المحلي فقط، يعود التطبيق إلى `.wasla-data/` عندما لا توجد سلسلة Neon صالحة. في النشر، تحفظ القواعد والتدفقات والحالات وسجل النشاط وبيانات جلسة QR المشفرة في Neon.

## عامل واتساب المستقل

يبني الأمر `pnpm run worker` عاملًا خفيفًا يملك اتصال WhatsApp Web وحده. يستعيد العامل جلسة QR من Neon تلقائيًا بعد إعادة تشغيله، ويقرأ قواعد الرد والتدفقات وإدارة الحالات مباشرةً من Neon. تبقى لوحة Vercel وسيطًا آمنًا: يرسل المتصفح طلبه إلى Vercel، ثم يمرر Vercel الطلب إلى العامل بسر داخلي لا يظهر للمستخدم.

| المتغير | يوضع أين | الغرض |
|---|---|---|
| `POSTGRES_PRISMA_URL` أو `DATABASE_URL_UNPOOLED` | العامل وVercel | الاتصال بنفس قاعدة Neon. |
| `WHATSAPP_SESSION_ENCRYPTION_KEY` | العامل فقط | قيمة عشوائية خاصة بطول 32 حرفًا على الأقل لتشفير جلسة Baileys. |
| `WORKER_SHARED_SECRET` | العامل وVercel | سر عشوائي طويل لحماية أوامر بدء QR والحالة وإعادة الضبط. |
| `WORKER_URL` | Vercel فقط | رابط العامل العام، مثل `https://wasla-worker.example.com`. |
| `PORT` | العامل | يضبطه مزود الاستضافة تلقائيًا غالبًا؛ لا تضفه إلى Vercel. |

أنشئ مفاتيح السر مرة واحدة على جهاز موثوق، ولا ترسلها في محادثة أو تضعها في Git. يمكن أيضًا استخدام زر التوليد بجوار حقل القيمة في Render، مع إبقاء مفتاح التشفير بطول 32 حرفًا على الأقل:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

عند نشر العامل، اجعل أمر البناء `pnpm install --frozen-lockfile && pnpm run build:worker`، وأمر التشغيل `node dist/worker/index.js`. استخدم `GET /health` لفحص أن العامل يعمل، ولا تنشر هذا المسار باعتباره أداة تحكم؛ أوامر جلسة QR محمية بالسر ولا يرسلها إلا Vercel.

## قواعد الأحداث

من القائمة الجانبية اختر **قواعد الأحداث**. ستجد محررًا يسمح بإنشاء أكثر من قاعدة، وتعديل اسمها والعبارة المشغلة ونص الرد وحالتها. حقل **رد خاص لرقم محدد** اختياري: عندما تتركه فارغًا يطبّق الرد على أي مرسل يطابق عبارتك، وعند إدخال رقم بصيغة دولية لا يرد النظام إلا على ذلك الرقم.

القواعد تُحفظ في `.wasla-data/rules.json` عبر واجهة `/api/rules`، ويقرأها موصل واتساب عند وصول كل رسالة. تكون القاعدة الافتراضية متوقفة في البداية، لذلك لا يرسل التطبيق أي رد حتى تقوم بتفعيل قاعدة مكتملة من الواجهة.

هذه الوظيفة مخصصة لردود واضحة ومحدودة في حساب تملكه أو تديره بتفويض، وليست للإرسال الجماعي أو الرسائل غير المرغوبة.

## قوائم الخدمات التفاعلية

من القائمة الجانبية اختر **التدفقات التفاعلية**. أنشئ قائمة باسم واضح، ثم حدد **كلمة البدء** التي يرسلها المستخدم، مثل `خدمات`. اكتب رسالة البداية، وأضف الفروع برقم واسم ورد خاص لكل خدمة. عند وصول كلمة البدء يرسل التطبيق القائمة، ثم يعامل الرسالة التالية من المستخدم كاختيار للخدمة.

| الحقل | مثال | النتيجة |
|---|---|---|
| كلمة البدء | `خدمات` | يرسل المستخدم الكلمة لفتح القائمة. |
| الخدمة `1` | `الاستعلام` | عند إرسال `1` يصل رد الاستعلام المحدد. |
| الخدمة `2` | `الدعم` | عند إرسال `2` يصل رد الدعم المحدد. |
| رقم محدد | `+9665XXXXXXXX` | يقصر هذه القائمة على هذا الرقم فقط. |
| رسالة الخيار غير الصحيح | `أرسل رقمًا من القائمة` | يعيد إرسال الخيارات ويبقي القائمة مفتوحة. |

تحتفظ الجلسة بالخيار المنتظر لمدة **15 دقيقة** في ذاكرة عملية التطبيق؛ إذا انقضت المدة، يحتاج المستخدم إلى إرسال كلمة البدء مرة أخرى. تكون القوائم متوقفة افتراضيًا، ولا تعمل قبل حفظها وتفعيل مفتاحها من الواجهة.

## إدارة الحالات والتفاعل التلقائي

من القائمة الجانبية اختر **إدارة الحالات**. تكون قاعدة الحالات متوقفة افتراضيًا. عند التفعيل، يعالج التطبيق الحالة فور استلامها عبر جلسة واتساب المتصلة، ويمكنه إرسال تأكيد مشاهدة وتفاعل تلقائي. التفاعل الافتراضي هو القلب `❤️`، ويمكن تبديله إلى أي رمز معروض في الواجهة.

| إعداد | السلوك |
|---|---|
| **كل الحالات** | يعالج حالات الجميع باستثناء الأرقام الموجودة في قائمة الاستثناءات. |
| **أرقام محددة فقط** | يعالج الحالات الواردة من قائمة الأرقام المشمولة فقط. |
| **الأرقام المستثناة** | لا يرسل مشاهدة أو تفاعلًا لحالات هذه الأرقام مطلقًا. |
| **تفاعل مخصص** | يعيّن رمزًا مختلفًا لرقم معين ويتقدم على التفاعل الافتراضي. |

تستخدم الأرقام صيغة دولية، مثل `+9665XXXXXXXX`. لا تُفعّل إعدادات الحالات أو ترسل أي تفاعل قبل حفظها وتشغيل مفتاح القاعدة. وبما أن الوصول يصل عبر اتصال واتساب Web قائم في العامل، فإن السرعة تعتمد على استمرار العامل واتصال واتساب ولا يمكن ضمان زمن تسليم ثابت.

## سجل النشاط والإعدادات

يفتح عنصر **سجل النشاط** قائمة الأحداث الفعلية المحفوظة، بما في ذلك بدء الجلسة وربط الحساب والرسائل والحالات وتنفيذ القواعد أو فشلها. يعرض سطح النظرة العامة آخر ثلاثة أحداث حقيقية فقط؛ لا يضع التطبيق أمثلة ثابتة مكان النشاط. يمكن مسح السجل من نافذته عند الحاجة.

يفتح عنصر **الإعدادات** حالة جلسة واتساب، ورقم الربط عند توافره، وآخر تحديث، وخلاصة الخصوصية. يحتوي كذلك على زر **إعادة ضبط الجلسة**؛ وهو إجراء صريح يسجل خروج الحساب ويمسح بيانات الربط المشفرة من Neon، ولذلك ستحتاج إلى ربط الحساب عبر QR من جديد.

## مساعد بسّام الشخصي

افتح **مساعد بسّام** من القائمة أو من زر الواجهة الرئيسية. المساعد متوقف افتراضيًا؛ لا يرسل التطبيق أي محتوى إلى Gemini قبل تشغيل مفتاح التفعيل ثم الضغط على **حفظ إعدادات المساعد**. يعمل المساعد كواجهة إرشادية فقط: لا يربط حسابًا، ولا يرسل رسالة، ولا يغير قاعدة أو حالة بدلًا عنك.

| الإعداد | الأثر |
|---|---|
| **مفعّل / معطّل** | يرفض مسار المحادثة أي طلب عندما يكون معطّلًا. |
| **موجّه** | يقدم اقتراحات عملية داخل نطاق لوحة وصلة. |
| **صارم** | يجيب بإيجاز ومن دون تخمينات أو أتمتة واسعة. |
| **مقفل** | يحصر الإجابات في الربط والقواعد والتدفقات والحالات وسجل النشاط. |
| **قراءة سجل النشاط** | خيار صريح؛ يرسل آخر 15 حدثًا فقط للمساعد عند تشغيله. يبقى متوقفًا افتراضيًا. |
| **تعليمات بسّام الثابتة** | نص إضافي يوجه أسلوب المساعد، لكنه لا يتجاوز حدود الخصوصية والأمان الخادمية. |

يستخدم الخادم المتغير `GEMINIAPI` فقط. لا تضع المفتاح في متغير يبدأ بـ`NEXT_PUBLIC_`، ولا تضفه إلى ملف أو إلى Git. توصي وثائق Gemini باستخدام متغيرات البيئة وعدم كشف المفاتيح في تطبيقات العميل [1].

## Neon وVercel

| البيانات | مكان الحفظ في Vercel |
|---|---|
| قواعد الرد | Neon، ضمن مستند `rules`. |
| قوائم الخدمات | Neon، ضمن مستند `interactive-flows`. |
| إعدادات الحالات | Neon، ضمن مستند `status-settings`. |
| إعدادات مساعد بسّام | Neon، ضمن مستند `assistant-settings`. |
| سجل النشاط | Neon، ضمن مستند `activity`. |
| جلسة QR واتساب | Neon في مستند منفصل ومشفّر؛ لا يعمل الاتصال نفسه داخل Vercel بل في العامل الصغير. |

يمكن فحص الاتصال بعد النشر من `/api/health`. عندما ينجح الاتصال ستعرض الاستجابة `"storage":"neon"`. تدعم وثائق Neon استخدام مشغلها الخادمي في Next.js، كما يحقن التكامل مع Vercel متغيرات الاتصال لكل بيئة منشورة [2] [3].

## واجهات التطبيق

| المسار | الغرض |
|---|---|
| `/` | لوحة التحكم والربط وإدارة الحالة. |
| `/api/health` | فحص جاهزية بسيط للخدمة. |
| `/api/rules` | قراءة قواعد الرد وحفظها من لوحة التحكم. |
| `/api/flows` | قراءة قوائم الخدمات التفاعلية وحفظها. |
| `/api/activity` | قراءة سجل النشاط المحفوظ أو مسحه صراحةً. |
| `/api/assistant/settings` | قراءة إعدادات مساعد بسّام وحفظها. |
| `/api/assistant/chat` | محادثة Gemini الخادمية بعد التفعيل فقط. |
| `/api/status-settings` | قراءة إعدادات مشاهدة الحالات والتفاعل عليها وحفظها. |
| `/api/whatsapp/session` | قراءة حالة العامل وبدء QR أو كود الربط عبر وكيل Vercel الآمن. |
| `/api/whatsapp/session/reset` | إنهاء الجلسة ومسح بيانات الربط المشفرة من العامل وNeon صراحةً. |

## ملاحظات الاستخدام

تستند طبقة الربط إلى مكتبة تتعامل مع بروتوكول WhatsApp Web. استخدمها فقط لحساب تملكه أو لديك تفويض واضح لإدارته، والتزم بسياسات واتساب. لا تضع بيانات جلسة واتساب في متغيرات عامة أو مستودع GitHub.
